# HYPRN MVP UI

## When to load

Load this skill before any change under `ui/src` or `ui/tests`, any change to a stylesheet, to `design-system/tokens.json` or to anything in `design-system/`, and before reviewing or accepting a screen.

## Read first, in this order

1. `design-system/README.md`: principles, content rules, visual foundations, implementation rules and checks.
2. `design-system/Layouts.md`: page compositions at the 1440 × 1000 reference viewport.
3. `design-system/Scientific-states.md`: how values, outcomes, claims and progress are worded and marked.
4. `design-system/SOURCE.md`: what each design-system file holds and the order of a design-system change.
5. The component notes in `design-system/components/` for every component you touch, then `design-system/Naming.md` and `design-system/Coherence.md`.

`docs/specs/ui-target.md` says where each piece of information lives; `design-system/Naming.md` is the authority for the words.

## Rules

- Build screens only from the components exported by `ui/src/design`. Never write a second rendering of a component that exists there.
- Colours, sizes, spacing, radii, shadows and type come only from tokens (`var(--…)` from `ui/src/design/tokens.css`). Never introduce a literal colour, px size, radius or font.
- `ui/src/design/tokens.css` is generated from `design-system/tokens.json` by `python3 ui/design_tokens.py`. Never hand-edit it; change `tokens.json` and regenerate.
- The served content security policy is `default-src 'none'; script-src 'self'; style-src 'self'; font-src 'self'`. Therefore: no inline styles (`style=`, `setAttribute('style')`, `cssText`), no runtime remote fonts, no icon fonts, no external URLs and no CDNs. The interface uses audited self-hosted Manrope with system fallback; scientific values and source retain system monospace. [Contour](../../../design-system/Contour.md) supersedes the former flat-surface and machined-corner rules.
- Icons are small inline SVGs passed as React nodes. An icon-only button carries an `aria-label`; every other icon sits beside a word.
- Status is shape + word + colour, never colour alone (`StatusTag`).
- A blank input reads "unassigned", a missing output reads "not computed", and zero is an explicit value shown as `0`. Never fill a blank with a default number and never show a missing output as `0` or an empty cell.
- Outcome facets stay separate: Execution and Criteria each have their own tag, never merged into one badge or score. Execution completion never means a criterion is met or a result is valid; a met criterion is not validity.
- Every screen works in the Day (light) and Control room (dark) themes and at 200% zoom without horizontal page scrolling.
- Every client action goes through the public HYPRN MVP API client (`HyprnMvpApi` in `ui/src/api.ts`); contract types in `ui/src/contract.ts` are generated by `python3 ui/generate_types.py` and never hand-edited.

## Checks

Run all of these before committing UI work; each must pass:

```sh
python3 ui/check_design_system.py        # no FAIL line (WARN lines are the recorded baseline)
python3 ui/design_tokens.py --check      # generated tokens current
python3 ui/check_ui_contract.py          # source wiring and named controls in ui/control-map.json
python3 ui/test_design_tooling.py
node ui/design_smoke.mjs
node ui/node_modules/typescript/bin/tsc --noEmit -p ui/tsconfig.json
npm --prefix ui run build
```

`ui/design-baseline.json` changes (`--update-baseline`) only for lines your change moved, and the commit says which. All checks run through `./hyprn-mvp dev check <group>`; combined-static includes the checks above.

## Definition of done for screen work

- One complete authorized UI journey per task; shared component adoption stays cohesive.
- Screenshots at 1440 × 1000 in light and dark, compared with the design-system reference images.
- Screenshots and other evidence stay outside the repository (in a scoped test folder or below the development evidence root), never in a tracked folder.
- DOM and browser tests prove behaviour, not visual fidelity; automated browser evidence is never human acceptance.
- Product-owner acceptance of a screen is recorded separately from the automated evidence.

## Commits

Stage explicit paths only (never `git add -A` or `git add .`); never stage `ui/node_modules`, `ui/dist` or evidence. Comments and test names state the invariant they protect, not the work item that introduced them.

## What changed

1. **Store schema** (`store.py`, `CREATE … IF NOT EXISTS`, additive): `agent_actors` (kind `agent`, delegating user, surface in `local_mcp`/`remote_mcp`/`claude_managed`/`openai_agents`, display name; unique per user and surface), `agent_delegations` (agent, delegating user, surface, study, ceiling `reader`/`writer`, canonical JSON effects, created, expiry, revocation time and reason; a check ties revocation time and reason; partial unique index `agent_delegations_one_live` for one unrevoked delegation per agent and study), `agent_api_sessions` (hashes of cookie and cross-site request values, delegation, agent actor, read-only flag, expiry), `agent_tool_tokens` (hash, `token_id`, delegation, audience fixed to `/mcp`, client label, created, expiry, revocation). Agent actors are never rows of `users`; the only `users` references are the delegating user's.
2. **Store functions:** `ensure_agent_actor`, `agent_actor` (agent row or `None` for a human), `live_delegation`, `create_delegation` (delegating user must be a member: 404; ceiling above the user's role or effects above the ceiling: 403; unknown ceiling, unknown effect, missing `read` or a past expiry: 400; a live delegation of the same agent and study is replaced with reason `replaced`), `revoke_delegation` (revokes the delegation's tool tokens and deletes its agent API sessions in the same transaction; idempotent), `revoke_all_agent_credentials`.
3. **`authorize` intersection** (signature unchanged): an agent actor needs a live, unexpired delegation of that study (404 otherwise), never gets `owner=True` (403), gets `write=True` only under the writer ceiling with a write effect `draft`/`record`/`submit` (403 otherwise), then the delegating user's current membership and role decide exactly as for that user. `list_studies` and `study_listing` return for an agent actor only its delegated studies whose delegating user is still a member. Membership SQL stays in `store.py` (one private reader `_membership_role`).
4. **Pre-study commands:** `command()` refuses every pre-study command of an agent actor (403) before any receipt lookup, except `study_create`, which needs `delegation_id` naming a live delegation of that agent with `record` under the writer ceiling while the delegating user is still writer or owner of the delegation's study (403 otherwise). `create_study(actor, command, name, *, delegation_id=None)` gives the Owner membership to the delegating user and none to the agent; the receipt stays in the agent's pre-study scope (`actor:<agent id>`, category `study_create`) with the agent as actor; the delegation is untouched. For an agent actor the pre-study replay in `command()` and `replay()` and the receipt read `receipt()` return the stored outcome only when the receipt is this agent's and the delegating user is still a member of the created study (404 otherwise), and never authorize the agent there. Human behaviour of all three is unchanged.
5. **`auth.py`:** `mint_agent_session` (15 minutes, capped at the delegation's expiry; values returned once; read-only unless writer ceiling with a write effect), `mint_tool_token` (`hyprn_mvp_mcp_` + `secrets.token_urlsafe(32)`, `ttl_hours` an integer 1–24, capped at the delegation's expiry, SHA-256 stored, token and `token_id` returned once), `verify_tool_token` (prefix and length bound, hash lookup, refuses expired or revoked tokens and dead delegations: 401), `revoke_delegation`; `authenticate` returns `kind` (`user`/`agent`), `actor_id`, `csrf_hash`, `expires_at`, `delegation_id`, `study_id`, `effects`, `read_only` and refuses an agent session whose delegation is no longer live. `recover()` also revokes every delegation (reason `owner_recovery`), tool token and agent API session in its write transaction. Nothing logs a token, cookie or cross-site request value.
6. **`agent_policy.py`** (new, imported only by `api`): `route_allowed(method, path, effects)` admits only `GET` on `/api/1/capabilities`, `/api/1/studies` and `/api/1/studies/{study_id}/…`; unknown effects raise.

## Decisions within the task

- **ADR-0005 applied:** the closed effect list is `read`, `draft`, `record`, `submit`, `outside_study` and `review`. A `reader` ceiling admits `read`, `outside_study` and `review` only (an agent for a Reviewer may record scientific reviews once the record exists, and nothing else); `writer` admits all six. `review` is not a write effect for `authorize`: a reader-ceiling delegation is refused every `write=True` call and its API session is read-only, so no write route admits it today. The review route's own admission comes with the review record (PKG-02). `docs/agents/tooling-spec.md` §3.2 still shows the ADR-0003 reader row; task 3.3 aligns it.
- Every delegation must hold `read`; delegations are created only through the store function (no route), by the operator command of task 3.4.
- Expired but unrevoked delegations still occupy the one-live index; `create_delegation` replaces any unrevoked delegation of the same agent and study, so renewal never fails on an expired one.

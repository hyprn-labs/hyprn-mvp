## What was built

- **One table in `store`**: `receipt_recovery(category, receipt)` (receipt `None` when missing), `RECEIPT_RETRY_AFTER_S = 2`, `RECOVERY_VALUES`. `committed` → `adopt`; `rejected` → `refused`; run `accepted_run`/`prepared`/`preparation_failed`/`dispatching`/`recorded` → `adopt`; run `uncertain` (and any state the table does not name) → `uncertain`; model `pending_remote` → `resend_same_command`; other `pending_remote` → `wait` + `retry_after_s`; missing → `resend_same_command`, for a run `wait` + `retry_after_s`. A run never yields `resend_same_command`.
- **Missing versus no access**: `Store.visible_receipt` (same authorization and scoped 404 as before; `None` for a missing receipt in a visible scope, including an agent's own `study_create` scope); `Store.receipt` keeps its behaviour on top of it. `ReceiptMissing` (a `DomainError` subclass, `data()` unchanged) carries the recovery; `edge.error_response` adds `recovery`/`retry_after_s` after the usual error fields only for it (`receipt_error_response`).
- **Routes** (`routes/commands.py`): both reads add the recovery after the owner's read and validation (the approach receipt still validated as `ApproachReceiptRead2`, the model receipt still reconciled first, the record closure still reauthorized); status codes, error codes, messages and every earlier body member unchanged.
- **Contract**: `PublicReceipt` gains required `recovery` (enum of the five values) and optional `retry_after_s` (1–60); new `ReceiptError` (= `Error` with the two optional members beside the others in `error`, same `required`); the 404 of the two receipt operations references it; their operation notes state each value. Regenerated with `application/generate_contract.py` and `ui/generate_types.py`.
- **Specification**: architecture §6.6 table gains the Recovery column and a "Recovery" paragraph.
- **UI** (`ui/src/api.ts`): `reconcile` follows `recovery` only (`adopt`/`refused` clear the command; `resend_same_command` makes it retry-ready; `wait`, `uncertain` and an answer without `recovery` keep it pending and not retry-ready; a 404 with `wait` or without `recovery` is rethrown); `retryOriginal` resends only after `resend_same_command`; `mutate` unchanged (no category comparison). Readers of `pending`/`retryReady` untouched.
- **Tests**: `test_receipt_recovery.py` (16 cases, registered in `api-a`): the whole table per category and state; run never resent; through the API — study and study archive (real commands), evidence (real), configuration (stored receipts), model (rejected; pending re-queried with the same command id through the unavailable modeling double; a recorded committed response with the coordinator's own checks stubbed), the three approach categories, both computational-record categories, every run state from the submission fixture; pre-study reads for a person and an agent (missing → 404 with `resend_same_command`; after the delegating user left the created study → 404 without recovery); a non-member and a foreign study get 404 without recovery; today's body members unchanged in every 200. `command-recovery.spec.ts` covers every value (13 cases).

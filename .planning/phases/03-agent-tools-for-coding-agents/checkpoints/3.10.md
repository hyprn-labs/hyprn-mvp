## What was built

- **Tables** (DDL in `schema.py`, created by `schema.ensure` with the attribution table; every statement in `records.py`). `agent_sessions`: session, delegation, token, surface, `mcp_session_id` UNIQUE, protocol version, client name and version (1–64 printable characters or NULL), display name, registry version, playbook and tool-definition hashes, state `active`/`ended`/`access_lost`, `api_calls`, `runs_submitted`, start and end times; triggers refuse DELETE, any change of the fixed columns, any state change once not `active`, and decreasing counters. `agent_actions`: action, session, delegation, study, call id, tool, effect, `args_sha256`, `command_ids`, `api_operations` (method, template, request id, status), `outcome_class`, `reason_code`, `reason_message` (≤ 512), `warnings`, `records`, `result_json` (writes only, ≤ 24 KB, CHECKed), state of the six values, created and completed times; UNIQUE(session, call id); index (study, created_at); triggers refuse DELETE, an insert in any state but `intended` or `refused`, any update of a row not `intended`/`reconciling`, a move back to `intended`, and any change of the intended columns. No column holds arguments, cookies or cross-site request values.
- **`limits.py`**: the D-11 constants (600 calls, 24 KB, 256 KB, 5 identical `invalid_input` in 120 s, 20/10/60 runs), the waiting run states (`accepted_run`, `prepared`, `dispatching`, `uncertain`), command-id counts per effect, the one-minute re-mint margin, journal bounds, and `run_refusal(requested, session_runs, queued)` (call cap, then session cap, then queue cap).
- **`sessions.py`** (`Sessions`): `open(grant, mcp_session_id, client_info, protocol_version)` refuses while the kill switch is off (`agent_disabled`) or the delegation is dead (`access_lost`), ends every active session of the same token (ND-7), stores the display name from the closed mapping `claude-code` → "Claude Code (local)", `codex-mcp-client` → "Codex (local)", otherwise "Coding agent (local)", and returns a `SessionHandle` without credentials. The delegated API session (`Auth.mint_agent_session`) is kept in memory only and re-minted when less than 60 s remain; `live()` confirms it through `Auth.authenticate` before every call.
- **`journal.py`**: the closed reason list with its HYPRN MVP messages (`REASONS`), `intend`, `refused` (admission refusal, inserted directly), `complete(records, warnings, result)`, `refuse`, `fail`, `uncertain`, `find`; placeholders are filled only with schema paths and schema-derived problems.
- **`runtime.py`** (`Runtime(store, auth, registry, api_app, origin, environ, *, stage, capabilities, clock)`, `call_tool(surface_ctx, call_id, name, arguments)` → `ToolOutcome(ok, content, action_id, state)`): admission in this order — kill switch (every call), session `access_lost`, live delegation (also before a stored outcome is answered), API-call budget, repeated errors, tool offered in the session, input ≤ 256 KB; then `intended` with fresh command ids for draft/record/submit tools; `Registry.invoke` with `RuntimeContext` (a `ToolContext` with the clock, the command ids and `admit_runs`, `record`, `warn`); one outcome. The call-bound API client counts every request atomically against the session budget (the 601st is never sent), journals each operation's route template (never a concrete path), and refuses a run POST that run admission did not admit. Access loss (a 403, an `access_lost` error, or a dead delegation found after an error) ends the session as `access_lost`, sticky. A duplicate call id returns the stored outcome of a write and answers a read again, with no second row. A write that may have changed something before failing is journaled `uncertain`, never "nothing changed". Exception text never reaches the agent or the journal.
- **Run admission** (`ctx.admit_runs(count)` by every submit tool): > 20 → `invalid_input`/`run_limit_call`; session journaled runs + count > 60 → `budget_exhausted`/`run_limit_session`; the agent actor's journaled runs (all its sessions and delegations in the study) whose state in `GET S/runs` is waiting + count > 10 → `busy`/`run_limit_queued` (the list is read only when the actor's journaled runs + count exceed 10; a journaled run absent from the list counts as waiting; more than 50 pages refuses).

## Deviations

1. **[Rule 3] Injected context.** `spec.py` is not in the file list, so `RuntimeContext` subclasses `ToolContext` in `runtime.py` (frozen, defaults only); the registry's validation is unchanged.
2. **Run admission placement.** The tool reports its run count through `ctx.admit_runs(count)`, so admission runs inside the call after the `intended` row; every refusal still happens before any submission and is journaled `refused` with its reason, and the call client refuses any unadmitted run POST (`failed`/`internal`, nothing sent).
3. **Journal functions** beyond `intend/complete/refuse/fail`: `refused` (admission refusal without an `intended` row), `uncertain`, `find`, `read`, `message`. Reason codes are enforced in `journal.REASONS`, not in a CHECK, so `configuration_not_ready` (3.32) needs no table rebuild; states and outcome classes are CHECKed.
4. **Agent-facing categories of runtime refusals**: kill switch `unavailable` (not retryable); API budget, repeated errors and session run cap `budget_exhausted`; queue cap `busy` (retryable); call cap `invalid_input`. Tool error categories without a code in the closed list are journaled as: `too_large` and `unsupported` → `invalid_input`; `pending`/`uncertain` → `uncertain`/`outcome_unknown`; `busy` from the API and any other → `failed`/`internal`. Task 3.20 owns the full error mapping.
5. **Replaced session.** A call on a session a newer `initialize` ended raises `SessionEnded` (no row; the surface answers as for an unknown session) instead of `access_lost`, since the agent's access did not change.
6. **Command ids** are a fixed pool per call (20 for submit, 4 for draft and record), written at intent time because the intended columns never change; the operations show which were used.
7. **The package docstring** in `agent_runtime/__init__.py` is not updated (file outside the list); it does not yet name `limits`, `sessions`, `journal` and `runtime`.

## Scratch and remaining risks

- **Risk 1 (product owner, 3.28):** under the literal rule "a call that would take the agent above 10 waiting or running runs is refused", one call can never submit more than 10 runs, so the per-call cap of 20 never binds. If 20 per call is meant to be reachable, the queue rule must count only runs already waiting before the call.
- The client names `claude-code` and `codex-mcp-client` are expected `clientInfo.name` values, to be confirmed by the client-facts probe (3.17, 3.19); an unknown name gets "Coding agent (local)".
- Runs counted for the session and queue caps are the runs journaled as records; a submission whose outcome is uncertain counts only the runs its tool reported before failing, until reconciliation (3.20) adopts the rest.
- "Identical" errors are the same tool with the same argument digest; the same error reached with different arguments is not counted.
- The surface call id is stored as given (bounded printable ASCII; for MCP it includes the client's JSON-RPC id).
- Every API call takes one short write transaction to count it against the budget.

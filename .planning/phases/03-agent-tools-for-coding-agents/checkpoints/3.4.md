## What was built

- **Tables.** `schema.ensure(store)` runs the runtime DDL on the store's connection (`IF NOT EXISTS`); `create_app` calls it when a store is given, the operator command after opening its store; `store` imports nothing of the package and gets no DDL. Table as specified (nine record kinds, `study` included; primary key (study, category, command, kind, record)); trigger refusing DELETE; no confirmer column. All SQL over the agent records is in `records.py`; `git grep -l agent_attribution -- application/src` lists only `schema.py` and `records.py`.
- **Kill switch.** `control.agent_enabled(environ)`: exactly `true`, otherwise off.
- **Delegations and tokens.** `delegations.issue_local(store, db, owner, study, *, expires_at)`: agent actor (user, `local_mcp`) "Coding agent (local)"; ceiling from the user's current role (Owner/writer → writer, reader → reader, non-member 404); effects `read`, `outside_study`; `create_delegation` revokes the live one (reason `replaced`). `tokens.mint_local` (default 8 h, 1–24; refused 403 while off; a failed mint revokes the fresh delegation), `list_for_study`/`owner_list` (metadata only), `revoke_in` (token and delegation, reason `revoked`, in the caller's transaction), `revoke(store, study, token_id=None)` (one token, or every live local delegation of the study).
- **Attribution.** `record(db, entry)`; `page` and `created_studies` (limit 1–100, opaque base64url keyset cursor over (recorded_at, category, command, kind, record), newest first). Each entry is shown only when its receipt exists in its scope (the study, or `actor:<agent>`/`study_create` with the created study id), is not rejected, names the entry's agent as actor, and that agent acts for the entry's delegating user. Delegator display name = user name.
- **Routes** (`agent_runtime/routes.py`, router appended last to `api.ROUTERS`; each has the human-only dependency, 403 for agent sessions): `GET S/agent/attribution`, `GET S/agent/access` (`installation_enabled`; per agent its latest delegation: `active`/`none`, or `ended` with `revoked` (ended_at = revocation), `expired` (ended_at = expiry), `membership_changed` (role no longer admits the ceiling; ended_at null, no time is recorded)), `GET S/agent/tokens` (Owner only, page of 100, cursor = token id), `POST S/agent/tokens/{token_id}/revoke` (Owner only, `{command_id}`, receipt category `agent_token_revoke`, replay returns the stored outcome), `GET /api/1/agent/attribution/studies`.
- **Operator commands** (`python -m hyprn_mvp_app.agent_runtime`): `mint-token` writes only the token and a newline to standard output; `list-tokens` and `revoke` print JSON without secrets; errors print the error code only to standard error.

## Deviations

1. **[Rule 3] `edge.py`**: `RouteDeps` gains `environ` (default `None`) so the agent router reads the environment from the composition object (step 6); docstring adjusted. No other line changed.
2. **`create_app(store, auth, model, *, environ=None, registry=None)`**: besides the inclusion, the STATE note of task 3.8 (composed registry) is applied: `registry` is passed to `route_allowed`; `environ` defaults to `os.environ`.
3. **Signature**: `issue_local` takes the store first (`issue_local(store, db, ...)`); the store's delegation functions are instance methods.
4. **Revocation route**: revocation runs `Store.revoke_delegation` (the primitive behind `Auth.revoke_delegation`) inside `store.command`, so revocation and its receipt commit in one transaction; `Auth.revoke_delegation` opens its own write transaction and cannot run inside the command.
5. **OQ-2**: the operator command prints the token as this task specifies; the credential-store hand-off and `--show-token` belong to the CLI tasks (3.14, 3.16).

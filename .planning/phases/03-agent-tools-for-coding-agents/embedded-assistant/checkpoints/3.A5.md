2026-10-20. Code commit `7c13a11`. Local demonstration, not full release qualification.

## Cause and correction

Study mamamia (`6c69c7cc-5f3c-49af-a84b-040f0f883f8c`) had no accepted turn or
provider session. Public POST returned HTTP 429, `limit_exceeded`, outcome unchanged,
empty diagnostics. Two prior conversations reserved USD 5 each against a USD 10 demo
ceiling. StudyAssistant treated every thrown send as uncertain, locked the draft and
showed Retry send. This was a definite admission refusal, not a provider delivery timeout.

The backend now returns a controlled diagnostic `assistant_budget_reserved`, explaining
that no message was sent and that an administrator must review the reservation ceiling.
The UI preserves editable text on unchanged outcomes; uncertain outcomes retain the same
command and locked payload for reconciliation. No provider retry, scientific execution,
permission or automatic budget-increase rule was added. Design-system and operator docs
record this distinction.

## Implemented boundary

`design-system/components/Collections.md` owns wording and coverage rules.
`CollectionStatus` consumes typed loading/failed/ready state, entity names,
optional local match count and scope. It renders count, empty/no-match, paging,
busy and retry consistently. API cursors and reads remain in application code.

`useCollectionRead` owns the repeated paged read lifecycle: initial versus append,
same-cursor retry including numeric zero, exact-ID deduplication, refresh replacing
rows only on success, stale/scope/API/session fences, and protected-data clearing.
Explicit refresh supersedes a pending page. Ordinary append failure retains rows
and retry cursor; protected clear resets retry to page one. Empty error detail is
still a failed state. Ownership and smoke checks enforce the shared boundary.

Adopted: configuration versions, analyses, analysis runs/versions/estimates, run
history, evidence library/picker, result picker, evidence version readers and
assumption evidence-version replacement. Home uses complete-list semantics.

Read-only dispositions: api.revisions uses api.list; BriefController and
AnswerController drain version cursors before ready state; StudyBrief/StudyAnswer
gate the initial selector on resolved state. These do not need redundant pagers.
EvidenceIndex owner completeness, exact saved member arrays, design points,
scientific run progress and fitting lifecycle retain their existing meaning.
Run API history list_page uses limit+1 and a continuation run ID, so the unknown
total remains unknown until next_cursor is null; no backend change was needed.

## Delivered journey

The generic public API accepts an explicit one-dimensional sampling design and later a
fit/predict request referencing genuine retained scalar runs. The dispatcher uses the existing
bounded stdio bridge and attested restricted worker. OpenMDAO 3.45.1 owns both actual
ResponseSurface and Kriging fits/predictions. AiiDA retains data-only canonical JSON input and
output files, process UUID, store UUID and artifact UUID. No serialized estimator is accepted.
Preview, basis and status reads perform no numerical work; candidate source executes only
through the existing isolated scalar path. All requests carry complete identity, fixed input
values, axis bounds, exact seed/counts, per-output tolerances and a declared rationale.

Public routes: POST `/api/1/studies/{study_id}/exploration-requests` and GET
`/api/1/studies/{study_id}/exploration-requests/{request_id}`. Responses retain full sample
inputs, complete query vectors, exact basis/source/configuration/runtime identities and the
selection token. Existing command receipts own pending/running/complete/uncertain states;
ambiguous work is never redispatched automatically. No new table or scheduler was added.
Limits are one axis, 3–16 training points, 2–16 checks, 1–32 outputs, 1–33 query points,
60-second bounded numerical worker operation, ten pending/running operations per study.
Assignments must use exact declared model units; this tracer performs no conversion.

Independent check failures are retained in the samples and denominator/counts. Missing
references produce null estimates with `incomplete_samples`, never zero. Observed tolerance
failure also produces unavailable estimates. Tolerance agreement is not physical validation.

The attested source inventory and worker image build include the new numerical module.
All existing inventory coverage checks remain closed; census expectations were updated
for one actual added file, not relaxed.

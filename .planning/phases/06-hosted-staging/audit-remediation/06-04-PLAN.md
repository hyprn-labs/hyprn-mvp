# Catalogue-backed monetary quantities

Owner steering: monetary changes must also belong to the units catalogue. This
is part of F12, required before this batch is pushed, not a separate follow-up.

## Outcome

An engineer or Assistant selects a monetary unit through the same catalogue as
other quantities. A real restricted calculation preserves its dimension, scale,
denominator and exact price basis into the saved answer. No dimensionless money,
unlabelled exchange rate, implicit inflation or study-specific display rule.

## Implementation

1. Add successor unit/model/execution contracts rather than changing frozen
   concrete definitions. Use the pinned OpenMDAO 3.45.1 catalogue generator and
   its existing USD and pax base units. Review a finite general-purpose set:
   USD, kUSD, MUSD, pax, USD/pax, USD/kg, USD/m**3, USD/h, USD/kW,
   USD/(kW*h), USD/J and USD/MJ. Admit only expressions actually verified by the
   pinned engine. Unsupported currencies stay unsupported; never label EUR as
   USD. Retain exact old catalogue identities for historical reads.
2. Derive monetary classification, numerator, scale and denominator from that
   same trusted catalogue. The in-progress ModelExplanationContent3 monetary
   basis must reference an exact quantity and its catalogue expression, with
   price year, economic basis and evidence. Remove independent free-text currency
   and denominator declarations as sources of unit authority. Validate against
   the exact selected model version. A supplied incompatible basis must fail.
3. Preserve the declared price basis through calculations and answer citations.
   Connections and comparisons must not silently combine different price years.
   Required conversions are explicit model calculations with their own evidence.
   Update quantity editors/readers, tools and /hyprn together, using catalogue
   discovery and shared design components. Never repair saved study data.

## Acceptance

Public API authoring, configuration and real restricted execution for compatible
USD scales and per-mass/per-energy cost; rejection of money-versus-dimensionless,
unsupported currency and mismatched monetary basis. Check exact immutable model,
configuration, run and answer pins; ordinary engineering units unchanged. Verify
catalogue digest/source pins and new attestation before staging execution.

Official engine source inspected:
https://github.com/OpenMDAO/OpenMDAO/blob/3.45.1/openmdao/utils/unit_library.ini
The existing engine supplies money: USD and passengers: pax; this task adds no
runtime unit registration or dependency. This is an implementation plan, not
evidence of completed catalogue support.

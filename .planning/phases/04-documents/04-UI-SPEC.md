# Phase 4 — UI Design Contract

> Visual and interaction contract for the Documents screens: library, collections, upload, text-first reader, search, annotations, citing from evidence and the cited-source history view. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This contract adds no visual values. Every colour, size, space, radius and type style below is a token from `design-system/tokens.json`, named exactly as there. Every screen element is an export of `ui/src/design`, or one of the design-system additions in "Design-system additions". A plan task must land those additions in `design-system/` and `ui/src/design` before any screen uses them. Where this file and `design-system/Naming.md` disagree on a word, Naming.md wins, and the change is made in Naming.md in the same task (Naming.md: "Any change to a reader-facing name is made in this file together with the interface change").

Sources used: `04-CONTEXT.md` (D-01–D-12, PD-4.1–PD-4.8), `04-RESEARCH.md` (UI section, open questions 1–8, assumptions A6–A7), `docs/specs/documents.md` §§2, 5–9, 11, 15, 17, 18, `docs/specs/ui-target.md` §§2–3, `design-system/*.md`, `design-system/components/*.md`, `design-system/tokens.json`, `ui/src/design/*`, `ui/src/Workspace.tsx`, `ui/src/EvidencePanel.tsx`, `EvidencePicker.tsx`, `EvidenceView.tsx`, and the document definitions and route registry in `contracts/schemas/model.schema.json`.

### A3 — Progress: measured variant

| Aspect | Contract |
|---|---|
| Purpose | Shows measured transfer progress ("1.5 of 4.0 MiB sent"). Indeterminate behaviour stays the default and is unchanged. |
| API | `Progress({ label, message?, value?, max?, valueText? })`. `value` and `max` are finite, non-negative safe integers (bytes) with `value ≤ max` and `max > 0`. `valueText` is the measured words. |
| States | Indeterminate when `value`/`max` are absent. Measured when both are valid. **Fail closed:** a non-finite, negative, unsafe or inconsistent pair renders the indeterminate track with `label` only. Numbers are never guessed, and a percentage or remaining time is never shown. |
| Markup | `<section class="hf-progress">`: `<p role="status">{label}</p>` (the stage in words, announced politely only when the stage changes), `<progress value max aria-valuetext={valueText} aria-label={label}>`, then `<p class="hf-progress__value">{valueText}</p>` (not live, so screen readers are not flooded per chunk), then optional `message`. |
| Tokens | Existing `.hf-progress` rules: `space-4` padding, `line` border, `surface` ground, `space-2` track height, `accent` track via `accent-color`, `radius-full` on the track. The value line uses the `small` style in `ink-2`, with numbers in `--font-mono`. |
| Keyboard / a11y | Not focusable. The stage words are the live region. `aria-valuetext` carries the measured words. |
| Docs | `design-system/components/Progress.md` gains a "Measured" paragraph. `Scientific-states.md` §Progress already requires measured counts. |
| Smoke | `ui/design_smoke.mjs` renders indeterminate, measured and invalid-pair (falls back to indeterminate). |

### A4 — Notice (banner)

| Aspect | Contract |
|---|---|
| Purpose | One shared recovery and state banner: upload outcomes, waiting states, stale edits, unavailable source, access loss. README: "A banner uses the `*-soft` ground with the matching text token." |
| API | `Notice({ tone, title, children, actions?, live? })`. `tone` ∈ `alarm, warning, advisory, ok, inert, running`. `title` is a short word or two, rendered as a `StatusTag` of the same tone. `live` ∈ `polite` (default → `role="status"`), `assertive` (→ `role="alert"`, only for alarm and access loss), `off`. |
| Visual | Ground `alarm-soft` / `warning-soft` / `advisory-soft` / `ok-soft` (`inert` and `running`: `surface-sunken`). 1px border in `alarm` / `warning` / `advisory` / `ok` (`inert` and `running`: `line-strong`). `radius-sm`. Padding `space-4`. Gap `space-2` between tag, message and actions. Message in `body` / `ink`. Actions are `Button size="sm"` in a wrapping row. |
| Rules | Never colour alone: the `StatusTag` mark and word are always present. Never used for normal states ("grey is normal"). `ok` only confirms a stored success. |
| Keyboard / a11y | Actions keep DOM order. The banner itself is not focusable. Showing a banner does not steal focus, except for access loss, which moves focus to the banner heading after clearing content. |

### A5 — TextReader (read-only source text)

| Aspect | Contract |
|---|---|
| Purpose | Escaped, read-only display of one bounded fragment of extracted or decoded text (one PDF page, or one window of lines of a text file), with line numbers, selection and a cited-passage highlight. It never renders HTML or Markdown. |
| API | `TextReader({ text, firstLine, label, selection, cited, onSelect, focusOffset })`. `text` is the fragment exactly as delivered (≤ 256 KiB). `firstLine` is the 1-based number of its first line. `label` is the accessible name ("Extracted text, page 4"). `selection` and `cited` are `{start, end}` half-open UTF-16 offsets within `text`, or `null`. `onSelect(range \| null)` reports UTF-16 offsets within `text`. `focusOffset` scrolls a passage into view. The component does no fetching and no codepoint conversion (the server converts and verifies, per documents.md §8). |
| Markup | `<div class="hf-reader" role="region" aria-label={label} tabindex="0">`. Each logical line is `<div class="hf-reader__line">` holding `<span class="hf-reader__num" aria-hidden="true">` (line number) and `<span class="hf-reader__text">` made of React text nodes only. Every text segment carries its source offset so DOM selection maps back to exact offsets. Lines are not list items. |
| Escaping | React text nodes only: no `dangerouslySetInnerHTML`, no Markdown or HTML renderer, no link detection. Bidirectional override and isolate controls (U+202A–U+202E, U+2066–U+2069), zero-width characters (U+200B–U+200D, U+FEFF) and C0 controls other than LF and TAB are shown as visible inert markers (for example `⟨U+202E⟩`, `small` style, `ink-muted`, `surface-sunken` ground, `radius-xs`). Each marker maps to that character's offset range, so they cannot reorder or hide text. |
| Type and space | Text in the `code` style (`--font-mono`, `type-code-size` / `type-code-line`, weight 400), colour `ink`, `white-space: pre-wrap`, `overflow-wrap: anywhere`, `tab-size: 4`. Line numbers in `code` style, `ink-muted`, right-aligned. `space-3` gap between the number column and the text. Wrapped lines hang under the text column, not under the number. Ground `surface`; the region's padding is `space-4`. |
| Highlights | Selection: `accent-soft` ground (the system's selection fill). Cited passage: `trace-soft` ground plus a 2px `trace` left edge on each line it touches (provenance colour only). The highlight is never the only signal: the screen always names the range in words ("Selected: lines 12–14", "Cited passage · lines 12–14"). |
| Selection | Pointer selection inside the region maps to `{start, end}`. Selections that extend outside the region are clipped. A collapsed selection is `null`. A reversed selection is normalised. |
| Keyboard fallback (part of the component) | Fieldset "Choose passage" with four labelled `TextInput type="number"` fields: "Start line", "Start character", "End line", "End character". Character positions count Unicode characters, start at 1 and include the end. The fields mirror any pointer selection; editing them updates `selection`. Invalid input (outside the fragment, end before start) shows an inline message — "Start must come before end." / "Line N is not on this page." — and clears `selection`. The fieldset sits below the toolbar, before the text. Unit tests cover astral characters (UTF-16 surrogate pairs) and combining marks. |
| Keyboard | The region is in Tab order so it can scroll with arrow and Page keys. The fieldset fields follow it. No extra Tab stop is added per line. |
| Zoom / themes | Wraps at any width. No horizontal scroll inside the region or on the page at genuine 200 % zoom. Both themes use token colours only. |
| Bounds | Renders one fragment (≤ 256 KiB, documents.md §11). The screen pages through fragments; the component never concatenates pages. |
| Smoke | `ui/design_smoke.mjs` renders plain text, a long unbroken line, an HTML/Markdown payload (shown inert), bidi controls (shown as markers), a selection and a cited range. |

## Screen contracts

Routes are hash deep links that name explicit IDs (study, document, version, extraction attempt, locator). A link to an unavailable, foreign or deleted resource shows that state ("… is not available. No other … is shown in its place.") and never opens the latest or a broader view instead.

**Slice gating (D-08, open question Q3).** Each surface renders only when its capability slice is advertised by the server and its route is implemented. Gates: library and upload; collections; extraction, reader and search; annotations and citations; usage. An absent slice means no tab, button, panel or empty frame — never a disabled future control. The Documents tab itself appears only when the library slice is advertised. A slice that is advertised but unavailable at runtime (for example extraction without current containment evidence) is a real state and shows its own message ("Text extraction is not available in this installation. The original can be downloaded.").

**Roles.** Readers (study role `reader`) see read actions only. Write actions are removed, not disabled (documents.md §4).

## Numbers and sizes

- Byte sizes: under 1 KiB "N bytes" ("0 bytes", "1 byte"); under 1 MiB "N.N KiB"; otherwise "N.N MiB". One decimal, binary units, `--font-mono`. A nonzero size never shows as 0. Exact bytes appear in Record details as "Size (bytes)".
- Counts are measured words with singular and plural forms: "1 document" / "12 documents", "1 page" / "12 pages", "Text is available for 3 of 12 pages."
- Dates and times: `2026-10-09 14:20` (24-hour ISO).
- Short IDs: the first 8 characters, monospace, display only. Full IDs and every hash appear only in Record details, labelled "SHA-256" (never "digest").

**Record details dialogs** (Naming rule 2):
- "Document version record": Document ID, Version ID, Original filename, Format (media type), Size (bytes), Original SHA-256, Uploaded by, Uploaded at, and when text exists: Text extraction ID, Parser (name and version), Text extraction SHA-256.
- "Citation record": Citation ID, Version ID, Original SHA-256, Text extraction ID, Quotation SHA-256, Annotation ID and revision.
- No AiiDA node identity, store name or command identity appears anywhere, including Record details.

## Keyboard, focus, themes and zoom (binding for every Documents screen)

- Every action is a native button, link or form control in DOM order. No custom key handlers except the existing `Tabs` arrows and the TextReader region's native scrolling.
- Library: Tab order is header → Uploads panel → Collections panel → search toolbar → rows (each row's actions in order) → "Load more documents". Collections are a plain list of buttons.
- Reader: back link → Download original → Record details → Read latest version → toolbar → Choose passage fieldset → text region → side column sections.
- Dialogs: `DialogFrame` / `ActionDialog` trap Tab, close on Escape (which runs the unsaved-changes check), and return focus to the invoking control. After a successful create or delete, focus goes to the new row, or to "All documents" after a collection is deleted.
- Unsaved changes (annotation editor, collection dialogs, citation and evidence drafts, an upload still sending) join the existing ordered editor guard. Wording: "Discard unsaved annotation changes?" / "Discard unsaved collection changes?" / "Discard unsaved citation changes?" with "Keep editing" and "Discard changes". For an active transfer: "Stop sending this file?" with "Keep sending" / "Stop sending".
- Access loss (confirmed denial or sign-out): protected content (rows, text, annotations, snippets, quotations from live reads) is cleared first, then the access-loss Notice shows the existing text "Access to this resource is no longer available." Stored evidence already shown in other tabs follows the shell's existing access-loss seam.
- Focus is always visible: 2px `focus` outline offset 2px; `focus-ring` where outlines clip.
- Light and dark themes for every screen and state. Reduced motion: the running mark is static (existing rule).
- Genuine 200 % browser zoom at a native 1440 × 1000 window (the `ui/tests/foundry-zoom.spec.ts` Chromium pattern, not viewport emulation): no page-wide horizontal scroll; "Upload documents", the dialog commit buttons, "Download original" and the cite actions stay reachable; only the versions `DataTable` may scroll inside its own box.

**Evidence of the above:** light and dark, keyboard-only and 200 % screenshots per screen and per state family, written under `HYPRN_MVP_UI_EVIDENCE_ROOT` (outside the repository). The checkpoint records automated evidence separately from the product owner's walk-through (D-10). Automated evidence is never human acceptance.

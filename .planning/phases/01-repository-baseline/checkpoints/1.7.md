### 1. Export size: schema identities instead of schema copies

`modeling_runtime.stage_native_inputs` no longer copies `contracts/schemas/model.schema.json` and `contracts/schemas/execution.schema.json` into the provenance support set (`support_sources()`); it writes `provenance-inputs/support/schema-identities.json` (`schema_identities()`: a schema version and, for each of the two schemas, its repository path, SHA-256 and length). The producer's unchanged inventory code ships it as `provenance/support/schema-identities.json` and lists it among the patched support records of `provenance/generator.json` (path, size, SHA-256, role). The modeling schema the service reads stays in the patched inventory (`provenance/patched/config/modeling.schema.json`). Narrow-only: no allowlist entry was added, the 32 MiB limit is unchanged. `modeling/provenance.md` states the rule. `test_fuel_native_provenance.py` asserts that the support set is the build inventory minus the two schemas, that the fixture carries no schema copy, that the recorded identities equal the repository schemas and appear in the inventory, and that the record passes `sensitive()`.

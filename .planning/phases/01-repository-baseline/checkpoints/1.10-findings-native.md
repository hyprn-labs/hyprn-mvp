# Debug record 1.10 — findings-native after its producer checkout was removed

Locations as in checkpoint 1.9: `<repo>` (this checkout), `<data root>` (`HYPRN_MVP_DATA_ROOT`), `<fixtures>` (`<data root>/fixtures`), `<fixed scratch>` (`<data root>/scratch`, exported as `HYPRN_MVP_SCRATCH_ROOT`), `<working root>` (`<fixed scratch>/hyprn-mvp-test-64068bbb-…`, the materialized working copy of the pinned fixture `native-20261013T143955Z`) and `<producer checkout>` (the temporary checkout in which task 1.9 ran the producer and captured the fixture). `CHECK+ <group>` means `python3 -B deployment/checks.py --group <group>` with the variables of checkpoint 1.9 and `HYPRN_MVP_SCRATCH_ROOT=<fixed scratch>`. Scanned terms are never quoted here.

## Symptom

`CHECK+ findings-native`, after `CHECK+ findings-native-preflight`: 1 failed. `execute_once` asserts that the new downstream run is `recorded` without history errors (`findings_native_fixture.py:1100`); AiiDA logs `output parser returned exit code<300>: Missing or invalid bounded worker output`; the `execute-once` child exits 0; the teardown then raises `Nonempty WAL requires quiescent backup; immutable read refused`. It passed in the 1.9 acceptance run and has failed since, on the current tree and on the 1.9 tree, while every other native group that runs the worker passes.

## Root cause

Test-fixture drift, not a product defect.

The pinned fixture retains the producer scope's `launch-worker`, the executable of the scope's AiiDA installed code (`filepath_executable=<working root>/launch-worker`). The harness writes it (`scoped_fixture.worker_wrapper_text`) so that the launcher of the tree that runs the scope executes: it runs `<producer checkout>/deployment/tests/scoped_fixture_launcher.py` with the reviewed interpreter. The producer checkout was a temporary checkout and has since been removed.

The continuation finds the producer's worker image gone, rebuilds and re-attests the worker in-process from the current tree (as designed), prepares the new run, and launches it through that retained wrapper. The interpreter cannot open the missing launcher file and exits 2 before any worker container exists; `result.json` stays empty, the parser correctly returns exit 300, and the run is recorded as failed. Two conditions are both needed: a wrapper bound to the producer checkout, and that checkout gone (a changed checkout would also fail, because its launcher would not match the attestation made by the current tree). During 1.9 the producer checkout still existed. Other native groups write a fresh wrapper naming their own tree.

The launcher, worker, attestation and result parser all failed closed as specified. No attested source, pinned digest or fixture byte needs to change.

- The removed worker image, or a rebuilt image or attestation the bundle does not expect: the rebuild and attestation passed, and the new bundle binds the rebuilt image.
- Host load, the 20 s wall limit or the 0.5 CPU limit: no worker container started.
- Spotlight indexing of the scratch root: the failure is a deterministic missing file outside the scratch root. No `.metadata_never_index` was added.
- The scratch-root path recorded in the fixture: the working copy is materialized at its recorded root and adopted only by its marker; the AiiDA paths are exact.

### What ruff does not do

- It parses and analyses source text; it never imports or executes project code, and it loads no Python plugins (rules are compiled in).
- With the configuration below it rewrites files only when `ruff format` or `ruff check --fix` is called. The ratchet calls only `ruff check` (read-only, `--output-format json`) and `ruff format --check`.
- It has no third-party runtime dependency. Network use during `check` and `format --check` is not expected; the first locked run should be done once with the network blocked to confirm it.
- It does not enforce a hard line limit with the formatter: the documentation says the formatter "only makes a best-effort attempt" at the limit, so `E501` still reports lines the formatter cannot wrap (long strings, comments, URLs excepted).

### Behaviour changes that matter here

Read from the 0.16.0 and 0.17.0 release notes (https://github.com/astral-sh/ruff/releases/tag/0.16.0 and `/0.17.0`):

1. **The default rule set is large.** Since 0.16.0 ruff enables 413 rules by default (59 before), and removed `E701`, `E702`, `E703` from the defaults. A bare `[tool.ruff.lint]` would therefore enable hundreds of unrelated rules and would not include the three the plan wants. The configuration must set `select` explicitly (replacing the default set).
2. **Markdown code blocks are formatted by default** (0.16.0). `ruff format` run on a directory would also rewrite fenced Python blocks in `*.md` files (the repository's documentation). Exclude `*.md` (documented setting `extend-exclude = ["*.md"]`) and pass explicit `.py` paths from the ratchet.
3. **Default Python version is now 3.11** when none is configured (0.17.0). `requires-python = "==3.12.15"` is the only version statement in `pyproject.toml`; set `target-version = "py312"` explicitly so the result does not depend on how ruff reads an `==` patch pin.
4. **Pragma comments are ignored when measuring line length** by the formatter, `E501`, `W505` and `I001` (0.17.0, stabilised; classed as breaking because imports may be reformatted). Baseline counts must be produced with exactly this version.
5. Output formats: the default `full` format now shows unsafe fixes; `format --check` accepts the linter's `--output-format` values (0.16.0). Use `--output-format json` for counts.

### What prettier does not do

- It parses and prints source text; it never executes project code. It runs only configured plugins, and the proposed configuration lists none. The configuration file is JSON (`.prettierrc.json`), not an executable `prettier.config.js`, which would run code on every invocation; keep it JSON.
- It makes no change unless `--write` is given; the ratchet uses `--check` only.
- `printWidth` is a target, not a hard limit (the documentation says so explicitly), and prettier has no lint rule for long lines. For TypeScript the ratchet therefore enforces formatting only, as the plan states.

## 4. Recommended configuration defaults

### Line limit: 100 characters, for both tools

- Matches the plan's suggested default. Ruff's default is 88 and prettier's is 80.
- Measured on the committed tree (heuristic counts, no tool run): 56,058 Python lines, of which **7,946 exceed 100 characters (in 179 of 191 files)** and 12,930 exceed 88; 98 TypeScript and `.mjs` files with 18,458 lines, of which 6,501 exceed 100 and 9,652 exceed 80. A 100-character limit is already far above what the code keeps to, so the baseline will be large whatever the limit is, and a limit below 100 would only enlarge it.

### Python (`pyproject.toml`, no editor-specific or absolute paths)

    [tool.ruff]
    line-length = 100
    target-version = "py312"
    extend-exclude = ["*.md"]

    [tool.ruff.lint]
    select = ["E501", "E702", "E703"]

    [tool.ruff.format]
    quote-style = "single"
    line-ending = "lf"

- **Rule sets for the ratchet: exactly `E501` (line too long), `E702` (several statements on one line, `;`) and `E703` (useless trailing `;`)**, as the plan names, and nothing else. `select` replaces the 413-rule default (see change 1 above). All three are listed in the rules index as stable (not preview) rules, in the pycodestyle "formatting" group. `E501` ignores a line that is one unbroken word, a line ending in a URL that starts before the limit, and pragma comments. Existing counts (token-based, heuristic): about 3,812 `;`-chained statements in 127 files and no trailing `;` (E703 starts at zero and stays a guard). `E701` (colon compound statements, `if x: y`) is optional and not proposed, because the formatter always splits them and the format check already catches them.
- **Quote style: single.** The existing code is 98 percent single-quoted (58,667 single-quoted against 5,388 double-quoted string tokens outside triple quotes; 172 of 187 files with strings are mostly single-quoted). Ruff's own default is double and its documentation recommends it, but `single` is a supported option; docstrings keep double quotes either way (as in the repository: 1,072 `"""` against 48 `'''`). Choosing `single` keeps most reformatted lines unchanged. Alternative: leave the default `double` and accept a quote change on every string of every touched file.
- **Formatter scope:** no `skip-magic-trailing-comma`, no `docstring-code-format` (default off), no preview mode, no import sorting (`I001` is not selected).
- **No `[tool.ruff]` `exclude` list for pinned or generated files**: those exclusions are read by `style_ratchet.py` from their owners (plan step 4) and are passed as an explicit file list. Note that explicit paths bypass `exclude` unless `force-exclude` is set, so the ratchet's own filtering is the only guard.

### TypeScript (`ui/.prettierrc.json`)

    {
      "printWidth": 100,
      "singleQuote": true,
      "semi": true,
      "trailingComma": "all",
      "endOfLine": "lf"
    }

- `semi`, `trailingComma` (default `all` since 3.0.0) and `endOfLine` (default `lf`) restate prettier's defaults on purpose, so that a later default change cannot move the format silently.
- **Quotes:** the existing TypeScript is about 88 percent single-quoted (9,356 against 1,291 lines containing a double quote) and 12,449 of 18,158 lines in `ui/src` and `ui/tests` end in `;`; JSX attributes are double-quoted (608 against 0 single-quoted), which is prettier's default `jsxSingleQuote: false`. So `singleQuote: true`, `semi: true` and the default JSX quotes keep existing style.
- Run it only on explicit `.ts`, `.tsx` and `.mjs` paths: prettier also formats CSS, JSON and Markdown, and `ui/src/design/tokens.css` is generated.
- Add no `.editorconfig` unless it is meant to drive the width: prettier reads `max_line_length` from it, which would override `printWidth`.

### Ratchet note for the plan (not a recommendation to change it)

The plan requires every file added or modified since the base commit to be formatted. With the numbers above (179 of 191 Python files have lines over 100 and 127 have `;` chains), touching any existing Python file will reformat most of that file in the same commit. That is intended by D-13, but it makes every later task's diff on an existing file larger than its own change. The product owner may prefer to accept this, or to restrict the format check to added files and ratchet only the violation counts for modified files.

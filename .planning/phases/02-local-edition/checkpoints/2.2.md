## Placement (decision recorded here, as the plan asks)

- **The refusal rule lives in the core**, `application/src/hyprn_mvp_app/locations.py` (stdlib only): synced folders on every OS (components starting `Dropbox`, `OneDrive`, `Google Drive`, `GoogleDrive`, or `My Drive`), macOS `~/Library/CloudStorage`, `~/Library/Mobile Documents`, `~/Desktop`, `~/Documents`, WSL2 `/mnt/<letter>`, a symbolic link as the path or any parent; given and resolved forms both checked; host facts (`Host`: system, WSL2 by `WSL_DISTRO_NAME` or kernel release, homes from the password database and `HOME`) injectable. Reason: three processes must apply the same rule — the local edition (`paths.py`), the installation loader (which the attested launcher will import in 2.3) and the application store, which runs inside the application container where neither the local edition nor the integration package exists. Injection from a local-edition composition root would have left the container's store and the attested launcher without the rule, so no injection is used.
- **Per-OS defaults live only in** `editions/local/src/hyprn_mvp_local/paths.py` (config, data root, tool cache, logs; XDG on Linux/WSL2; resolution flag → `HYPRN_MVP_*` → configuration → default → question; `location_unresolved` / `location_refused`, exit 2). It imports the core rule from this checkout's `application/src`.
- `Store.__init__` and `checked_root` (computational record root) call `refuse_location` before creating anything; the `/tmp` exemption and the CloudStorage-only check are gone. Scoped stores pass because scope roots are canonical, off-cloud folders (no exemption).
- `test_module_boundaries.py` not edited: `installation.py` is not imported by any attested module yet, so the attested set and `execution_source_hashes()` are unchanged in this task (`locality-contracts` 117 passed). In 2.3 the attested set grows by **two** files (`installation.py` and `hyprn_mvp_app/locations.py`), not one.

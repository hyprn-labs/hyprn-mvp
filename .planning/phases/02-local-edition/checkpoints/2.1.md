## What exists now

- `hyprn-mvp` (POSIX sh, 0755): refuses unsupported hosts (macOS on Intel with the D-05b reason from `tools.json`, musl Linux, other systems: exit 3) and a checkout or tool cache in a synced folder (Dropbox, OneDrive, Google Drive on every OS; on macOS `~/Library/CloudStorage`, `~/Library/Mobile Documents`, `~/Desktop`, `~/Documents`; on WSL2 `/mnt/<letter>/…`: exit 2); resolves the tool cache (`HYPRN_MVP_TOOLS_DIR`, else macOS `~/Library/Caches/hyprn-mvp/tools`, Linux `${XDG_CACHE_HOME:-~/.cache}/hyprn-mvp/tools`), refusing a relative, unnormalized, synced or in-checkout value; removes every ambient `UV_*` setting except `UV_SYSTEM_CERTS`/`UV_NATIVE_TLS` and sets `UV_NO_CONFIG=1`, `UV_PYTHON_PREFERENCE=only-managed`, `UV_PYTHON_INSTALL_DIR`, `UV_PYTHON_BIN_DIR`, `UV_CACHE_DIR` (all in the tool cache) and `UV_PYTHON_INSTALL_MIRROR` before any uv run; downloads uv with `curl --proto '=https' --tlsv1.2 -fsSL` to a temporary folder, verifies SHA-256 (`shasum -a 256` on macOS, `sha256sum` on Linux) and size before extraction, places it by one rename and checks `uv --version`; `uv python install --no-bin 3.12.15`; `uv sync --frozen --no-build --exact --no-install-project --group contract`; then `exec <contract env>/bin/python -I -B -c <runpy of hyprn_mvp_local from editions/local/src>`. It never executes another Python.
- `pyproject.toml` + `uv.lock` (sha256 `bdf953870ec38f8afd5c9bcd967cd02b9bdbf4433b99d6a12b38949e8c265c7c`): non-packaged root project, two conflicting exactly pinned groups (`contract`, `native`), `requires-python ==3.12.15`, `environments` and `required-environments` limited to macOS arm64 and Linux x86_64/aarch64. `.python-version` `3.12.15`.
- `hyprn_mvp_local` (`editions/local/src`, stdlib only; `editions/local/pyproject.toml` declares it, never installed): `version [--json]` prints uv, Python (version and BUILD tag of the managed interpreter), `tools.json`, `uv.lock` and `pyproject.toml` digests, both locked environments and the release identity (none installed; checkout commit); `dev check <group> | --list [--class]` installs both groups (`--frozen --no-build`; contract `--exact`; native `--inexact` plus the authored AiiDA plugin registration), verifies that each environment's distributions equal its group (plus the plugin for native) and refuses any difference, then execs `<native env>/bin/python -I -B deployment/checks.py` without `HYPRN_MVP_NATIVE_PYTHON`/`HYPRN_MVP_CONTRACT_PYTHON`. Toolchain logic is in `toolchain.py`.
- Runner: `scoped_fixture.APPROVED_PYTHON`/`APPROVED_CONTRACT_PYTHON` = `local_paths.locked_python('native'|'contract')` = `<tool cache>/envs/<group>-<first 16 hex of the uv.lock SHA-256>/bin/python`; children still receive them as `HYPRN_MVP_NATIVE_PYTHON`/`HYPRN_MVP_CONTRACT_PYTHON` (browser configurations and managers read them there) and receive `HYPRN_MVP_TOOLS_DIR`; `checks.py --group` refuses unless it runs under the locked native interpreter; the per-group exact-interpreter guards are unchanged and now compare against the locked environments; the live fence treats the tool cache as read-only.

## Deviations from the plan

1. **One `uv.lock` with two conflicting groups instead of a three-member workspace.** The plan's fallback ("two locked projects, contract and native") applies; the two sets are two exactly pinned dependency groups of one non-packaged root project, declared conflicting, so one lock file and one digest cover both. `application`, `integration` and `editions/local` are not workspace members: making `integration` a member would lock `openmdao` and the worker set, and installing any member needs a build backend.
2. **No build backend fetched (audit D6).** The environments install no package of the checkout (`--no-install-project --no-build`). The CLI runs from `editions/local/src` through `runpy` under `python -I -B` instead of `-m` of an installed package, and the integration package's AiiDA entry points come from an authored metadata-only distribution in the native environment (the Phase 1 environment and `native_environment.py` already use the same registration). setuptools' exact pin and audit move to the first wheel build (task 2.5).
3. **Files beyond the task list:** `deployment/local_paths.py` (`HYPRN_MVP_TOOLS_DIR` passed to scoped children, `locked_environment`/`locked_python`), `deployment/tests/live_fence.py` (tool cache read-only; without it the fence would refuse the managed CPython below the data root), `editions/local/src/hyprn_mvp_local/toolchain.py`, `docs/legal/licensing.md` (uv and CPython rows, L6).
4. `tools.json` keeps no uv or CPython pin for macOS x86_64 (D-05b); its refusal reason is recorded there and in the audit's §10.
5. `test_shim.py` is not a runner group (no group registered in `checks.py`, which other tasks edit); its command is above.
6. `checks.py --group` now refuses any interpreter but the locked native one, so `python3 -B deployment/checks.py --group …` (the Phase 1 command still shown in `AGENTS.md` "Running checks") is refused with a message naming `./hyprn-mvp dev check`. `--list` stays available everywhere.

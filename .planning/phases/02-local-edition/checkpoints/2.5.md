## What changed

### Locks and build settings

- **`deployment/locks/native-host.txt`.** This is the reviewed native set N: the `native` group of `uv.lock` without ruff, 89 distributions. It was exported by `uv export --frozen` with every hash from `uv.lock`, and nothing was added.
- **`deployment/locks/build-backend.json`.** It pins the flit_core wheel's URL, size and SHA-256.
- **Both `pyproject.toml` files** declare `[build-system] requires = ["flit_core==4.1.0"]`. The integration package also gained a `description`, because flit requires one.

### `deployment/native_environment.py`

**`prepare(root, source, *, tools, cache)`** builds the environment as follows:

1. Before any read, it refuses a root that is already populated.
2. It refuses a root that already holds any `venv-*`, `locks/native-installed.json` or `licenses/native/`.
3. It refuses a snapshot package whose build system is not exactly the pin. This check runs before any effect.
4. It checks uv and CPython in the tool cache against `tools.json`. The CPython check covers version 3.12.15 and the BUILD file `20261003`.
5. It fetches the backend wheel and verifies its size and SHA-256.
6. It builds each package wheel offline from a staged copy of the snapshot, with `SOURCE_DATE_EPOCH` fixed. The flags are `uv build --wheel --offline --no-index --find-links <verified> --build-constraints <hashed> --require-hashes`. These flags were checked against `uv build --help` of uv 0.12.24 and in real runs.
7. It creates `venv-<lock16>` with the pinned interpreter's `-m venv --without-pip`, which writes no `.pth` file. It does not use `uv venv`, because that writes `_virtualenv.pth`.
8. It installs the locked set with `uv pip sync --require-hashes --no-build --strict`.
9. It installs the wheels with `uv pip install --no-deps --require-hashes --offline --no-index`.
10. It verifies the result. The distributions must be exactly the expected set and every RECORD hash must match. There must be no `.pth` file and no `direct_url.json`, and the project modules must be byte-identical to the snapshot.
11. It writes `locks/native-installed.json`, `licenses/native/` and `evidence/native-environment.json`.

On failure, `prepare` removes what it created.

The other operations:

- **`extend(root, binding)`** is the previous worker-inventory step, moved unchanged in behaviour: worker licences, `selected.json`, and the wrapper through `write_launch_worker`.
- **`initialize(root, configuration)`** creates the profile `installation.profile_name(configuration)`, which is `hyprn-mvp-local-<id8>`. It fixes `profile_name()`, which read a nonexistent `launcher.profile` attribute.

### Retired runtime removed

The aiida-core hashes in the lock still equal the reviewed artifacts in `pins.json`, a fact a test now asserts. The retired-runtime location was therefore removed:

- `local_paths.old_runtime_root`;
- `PRIOR`, `SITES` and `CONTRACT_PYTHON` in `native_environment.py`;
- the old copy-from-development-interpreter `prepare`.

The guard now asserts that the resolver is gone.

### Tests and group registration

- **`deployment/checks.py`**, additive block only: the must-pass group `native-environment`, with target `deployment/tests/test_native_environment.py`, unit fence and no needs.
- **`test_deployment_hardening.py`**: two tests were updated to the new signatures. The populated-root refusal now runs for `prepare` and `extend`, and the wrapper AST check now covers `extend` and `reuse_reviewed` and confirms that `prepare` writes no wrapper.

### Attested set

No attested source, `pins.json` or contract schema changed (`git diff 5b96120..HEAD` on `integration/src`, `application/src`, `contracts` and `deployment/pins.json` is empty). Re-attestation is therefore not needed. `native_environment.py` and the lock files are outside `execution_source_hashes()`.

## Remaining risks

- **Installed project modules cannot run on their own.** `hyprn_mvp_app.contracts`, which is attested, reads `contracts/schemas/*.json` relative to the source tree. Importing it from `site-packages` raises `FileNotFoundError` (checked). The environment therefore relies on the release binding putting the snapshot's `application/src` and `integration/src` first, as the entry-point test does. Its failure mode is fail-closed. Changing it touches attested code (2.8c/2.8).
- **Not yet wired.** Nothing calls `prepare` yet: setup and start wiring is 2.11. The launch wrapper still runs the launcher under `HYPRN_MVP_NATIVE_PYTHON`, as before (`extend` and `require_launch_worker` are unchanged); the switch to `venv-<lock16>/bin/python` belongs with start in 2.11. The CLI `prepare` uses `BINDING.source` and the tool cache's `uv-cache`, and has not been run against a release snapshot, because none exists before 2.8.
- **Unsatisfied project metadata.** The app wheel declares fastapi, uvicorn and pydantic 2.14.0, and the integration wheel declares openmdao. None of these is in N, and N has pydantic 2.13.5. The wheels are installed with `--no-deps` and never checked for metadata consistency, which is by design. A future `pip check`-style verification would refuse them.
- **Network needed.** `native-environment` downloads N (about 33 MB) and the backend wheel into its scope on every run. The group fails without network. It declares no `network` need, because the runner has no such need kind.
- **uv writes a timestamp.** uv adds `uv_cache.json` with a timestamp to the dist-info of the locally installed wheels. It is not module content and is not compared.

# Checkpoint 2.5: native host environment from pinned packages (stopped at the build-backend audit)

## Status: blocking product-owner checkpoint

Task 2.5 builds non-editable wheels of `hyprn-mvp-app` and `hyprn-mvp-integration`, which needs a build backend. Decision D6 (b) puts the exact build-backend pin and its audit at the first wheel build of the checkout's packages, and STATE makes that audit a blocking product-owner checkpoint. The task therefore stops before any product change. The record for the decision is `phases/02-local-edition/2.5-build-backend-audit-draft.md`. It compares three options: setuptools 84.0.0, flit_core 4.1.0 (recommended) and uv_build 0.12.24.

Findings that need the product owner:

- **setuptools 84.0.0, the backend STATE names.** It vendors autocommand 2.2.2 under **LGPL-3.0**. Under the permissive-licence rule this is a licence conflict that needs review, even though it is build-time only. setuptools also ships a startup `.pth` file and Windows executables.
- **flit_core 4.1.0.** It is pure Python under BSD-3-Clause, with no dependencies, no `.pth` file and a PyPI attestation. Choosing it changes the backend named in STATE.
- **uv_build 0.12.24.** It comes from the audited uv release. It carries a native binary per platform, contains one MPL-2.0 crate and has no PyPI attestation.

All three have no OSV advisory. The control queries returned advisories as expected.

## Facts established for the resumed task

- **Native host lock.** It is the `native` group of `uv.lock` minus ruff: 89 distributions, which is set N exactly. No package or version outside the audit is needed apart from the build backend.
- **aiida-core wheel.** Its SHA-256 in `uv.lock` equals `deployment/pins.json` `verified_artifacts`. Once prepare installs from the hashed lock, `old_runtime_root` (`local_paths`, `native_environment.PRIOR`, the guard entry) can be removed in this task.
- **Package data.** Neither `application/src` nor `integration/src` holds non-`.py` files, so no package-data configuration is needed.
- **Attested set.** `deployment/native_environment.py`, `deployment/locks/` and both `pyproject.toml` files are outside `execution_source_hashes()`. Nothing planned for 2.5 changes the attested set or `pins.json`, so no re-attestation is expected.
- **App wheel metadata.** The app wheel declares fastapi, uvicorn and pydantic 2.14.0. Because it is installed without dependencies into an environment with pydantic 2.13.5 and no fastapi, its metadata will not be satisfied there. The host side imports only attested modules, which need jsonschema and rfc8785, both in N. The resumed task should record this and must not run a metadata consistency check that would refuse it.

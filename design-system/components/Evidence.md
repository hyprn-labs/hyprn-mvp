# Evidence

One presentation for evidence everywhere: the library, the picker, the model details panel, input, criterion and context attachments, and run history.

- A library or picker record shows a three-line excerpt and **View evidence**. The dialog leads with the title and original content. Citation relationships read "Background for this statement", "Supports this statement" or "Challenges this statement". Non-empty source references are a numbered list of inert text. Stored resource names, versions and scope belong in Record details; explicitly study-scoped records say **Study evidence** there. A reference is never fetched automatically, embedded markup is never executed, and a missing scope is never inferred.
- Assumption and limit attachments use the same compact row layout. Each attachment is a compact named record with its own direct **View evidence** action; there is no intermediate **Evidence (N)** dialog. Several attachments stay independently inspectable. Editable attachments may offer **Remove attachment**, which changes only the owning draft. "Add evidence" uses the evidence picker and the guard for uncertain commands.
- Agent authorship remains visible beside the evidence note. It identifies who wrote the note, separately from the authority of its cited source.
- **Record details** in the evidence dialog shows the evidence family, version and resource identifiers. A record without a stored scope says **No scope.** here only. Raw `kind` and scope format version are not product fields; **Download evidence record** keeps the entire stored JSON. Empty or redundant context and reference sections are omitted. Version discovery is explicit in the library; choosing another version never silently replaces an attachment.
- A missing attached record says **Evidence unavailable**. A historical view reads the stored snapshot, never today's library.
- Run Evidence puts "Evidence used by this run" before the "Run files" table. File categories are presentation filters: Calculation records, Executable program, Provenance & licenses, All files. Search and 20-row pages never hide a file permanently. Details shows the SHA-256 and ID; previews are bounded at 64 KiB and downloads keep all bytes. Generated files are read-only provenance ("Read-only run file"); a missing file says "This run file is unavailable."
- A note kept with a run is evidence of its recorded context, not scientific validation.
